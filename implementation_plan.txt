============================================================
0. PROJECT PRIORITY
============================================================

The project is being judged primarily on:

1. Code quality
2. Security features
3. Functional correctness
4. Quality of the AI workflow
5. UI/UX and demo quality

Therefore, do NOT optimize only for speed. The implementation must remain clean,
secure, modular, validated, and maintainable even though the competition has a
short development window.

IMPORTANT AI AGENT RULE:
Before saying anything to the user or claiming that a task is complete, inspect
and verify the relevant code, files, configuration, and runtime behavior.
Do not assume that something works because it was written.
Test/inspect first, then report the result.

Do NOT claim:
- "Implemented" without checking the implementation.
- "Fixed" without reproducing/testing the issue.
- "Secure" without inspecting the relevant security controls.
- "Working" without actually validating the behavior.

Before every response to the user:
1. Review the current task state.
2. Inspect relevant files.
3. Verify changes.
4. Run appropriate tests/checks where possible.
5. Update the required context files.
6. Only then report what was actually completed.

Never fabricate test results, security guarantees, API responses, or implementation
details.

============================================================

These four files must exist at the project root:

ARCHITECTURE.md
TASK.md

These files are mandatory project memory.

After EVERY completed task/subtask:

1. Update PROJECT_CONTEXT.md

     whenever relevant.

2. Update ARCHITECTURE.md
   - Update architecture, data flow, APIs, database, folder structure,
     dependencies, security decisions, and technical decisions whenever changed.

3. Update TASK.md
   - Current objective
   - Requirements
   - Completed work
   - Current status
   - Current problem
   - Expected behavior
   - Next step

4. Update CHANGELOG.md
   - Short record of Added / Changed / Fixed / Security changes.

IMPORTANT:
The context files must represent the ACTUAL state of the codebase.
Never write planned functionality as if it already exists.

At the beginning of every new task, read:

PROJECT_CONTEXT.md
ARCHITECTURE.md
TASK.md
CHANGELOG.md

Do not modify unrelated features.

============================================================
2. PROJECT GOAL
============================================================

ProjectForge is an AI-powered platform that helps final-year students transform
their skills, interests, experience, team size, available time, and constraints
into practical project ideas and development guidance.

Core workflow:

Student Profile
    ->
Relevant Curated Knowledge
    ->
AI Project Recommendations
    ->
Project Selection
    ->
Evaluate Project
    ->
Blueprint
    ->
Development Plan
    ->
AI Improvements
    ->
Existing Project Check
    ->
AI Capability Check

The AI acts as a project mentor throughout this workflow.

7. PHASE 3 - OPENAI INTEGRATION
============================================================

Objective:
Securely connect the backend to OpenAI.

Architecture:

React
  ->
Express Backend
  ->
OpenAI API
  ->
Express Backend
  ->
React

NEVER:
React -> OpenAI directly

Tasks:
- Install/configure OpenAI SDK.
- Create openaiService.
- Store API key only on backend.
- Create a test endpoint/service.
- Implement timeout/error handling.
- Implement structured output validation.

Security:
- API key only in server environment variables.
- Never return API key to client.
- Never log API keys.
- Avoid logging full sensitive user input.
- Validate request body.
- Add request size limits.
- Add basic rate limiting if practical.
- Handle upstream errors safely.
- Do not expose stack traces in production responses.

Testing:
- Valid OpenAI request.
- Missing API key.
- Invalid request.
- OpenAI timeout/failure.
- Malformed AI response.
- Confirm frontend bundle does not contain secret.

Update all context files.

27. FINAL DEVELOPMENT RULES
============================================================

1. Build the simplest solution that satisfies the requirement.
2. Security is part of the feature, not a final decoration.
3. Validate all external and user-controlled input.
4. Never trust AI output without schema validation.
5. Never expose secrets to the client.
6. Never claim originality without evidence.
7. Never claim tests passed without running them.
8. Never claim a security control exists without verifying it.
9. Never modify unrelated features.
10. Read the four context files before every new task.
11. Update the four context files after every completed task.
12. Keep architecture consistent unless there is a documented reason to change it.
13. Prefer reusable services/components over duplicated code.
14. Keep AI prompts versioned/organized and separate from route handlers.
15. Keep business logic out of UI components.
16. Centralize error handling.
17. Use structured API contracts.
18. Keep dependencies minimal.
19. Test the changed functionality before moving forward.
20. Before reporting completion, inspect the actual implementation and state exactly
    what was verified.

============================================================
28. DEFINITION OF DONE
============================================================

A task is DONE only when:

[ ] Implementation exists.
[ ] Relevant code was inspected.
[ ] Relevant tests/checks were run.
[ ] Errors were addressed or explicitly documented.
[ ] Security implications were considered.
[ ] Context files were updated.
[ ] CHANGELOG was updated.
[ ] TASK.md describes the next step.
[ ] No unrelated functionality was broken.

The project is DONE only when the core workflow works end-to-end, the application
builds successfully, security controls are implemented and verified, and the
codebase is clean enough for a judge to inspect without discovering a digital
crime scene.
